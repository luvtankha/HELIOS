# HELIOS final engineering review

Audit window: 4–5 October 2026. Final local regression: 5 October 2026, Asia/Calcutta.

This review implements the supplied final-review checklist. It covers the current Hindi/Hinglish native-audio intake, the Java patient backend, Python voice gateway, shared PostgreSQL database, Express doctor backend, Next.js patient/doctor interfaces, startup scripts, dependencies and documentation. An inventory covered 781 non-generated project files at the first audit checkpoint. Active execution paths and their contracts received targeted source review; legacy documentation, fixtures and auxiliary routes were inventoried and checked through applicable suites. This is not a claim that every line, clinical scenario or historical screen was exhaustively validated.

## 1. Final status

**PRESENTATION READY WITH NON-BLOCKING LIMITATIONS**

The defined local hackathon workflow passed: Hindi native-audio intake → structured facts and identity → specialty routing → authenticated doctor dashboard → clinician review → persisted review after refresh. Three separate real Gemini sessions passed. The complete development stack and packaged local production stack both started. The expanded browser suite passed in both modes after repairs.

This status applies to a supervised demonstration using synthetic data on this configured PC. It does not certify clinical use, emergency triage, public hosting, every device or unlimited provider availability. No unresolved P0/P1 issue was identified in the tested main workflow. Remaining limits and an unresolved development-only dependency advisory are listed below.

## 9. Demo instructions

1. From the project root, use `pnpm start` with the prepared builds and private .env. Wait for all services. If source changed, run `pnpm build` and `backend-java/mvnw.cmd clean package` first. For initial setup, follow README installation/configuration steps.
2. In a second terminal, run `pnpm presentation:check`. Confirm all four services pass. Provision the configured local doctor with `pnpm local:doctor` only when needed.
3. Open `http://localhost:3000/patient`, accept Hindi consent, and allow microphone access. Use an invented identity and a mild synthetic fatigue scenario that matches the configured doctor. Answer the follow-up actually asked.
4. Show the listening/speaking feedback and completed intake. Explain that model audio is native and clinical fields are recorded separately.
5. Open `http://localhost:3000/doctor/login`, sign in as `helios-local` using the private configured access code, and open that patient. Show facts, evidence references, routing and brief.
6. Open Verification → Live intake, review a synthetic fact, verify/correct it, and refresh the patient workspace to show persisted review status.
7. Use the completed patient's **नई बातचीत शुरू करें** action for the next demo. Keep the README and beginner judge Q&A available for explanation.

Before the event, run one physical-microphone rehearsal. Do not call an automated synthetic recording a live human microphone test. A recorded backup must be labeled as recorded.
